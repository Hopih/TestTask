# История работы с AI

Ниже — 5 показательных промптов этой сессии. Писал человек, выполнял агент Cursor.

## 1. Исходное ТЗ сервиса заявок

**Промпт (сжато):** создать локальный репозиторий, мини-сервис учёта заявок: форма (имя, телефон, комментарий, источник), список, статусы «Новая / В работе / Успешно / Отказ», смена статуса, фильтр, сохранение, аккуратный UI. Плюс один API endpoint для внешней CRM (создать заявку и получить список). Нужны README, история промптов и Git. Стек: ASP.NET + React.

**Результат:** агент начал проект с нуля, а не дописывал чужой шаблон.

**Что доработал сам человек / следующим сообщением:** имя репозитория и выбор PostgreSQL вместо решения «на усмотрение агента».

## 2. Имя проекта и база

**Промпт:** имя папки — `TestTask`; «лучше используй PostgreSQL как БД, остальное по твоему усмотрению».

**Результат:** целевой путь `~/Projects/TestTask`, отказ от SQLite/Docker как основного варианта.

**Что пришлось поправить:** MCP `create_project` на Windows не смог сделать `git init` (`spawn /bin/sh ENOENT`). Репозиторий инициализировали обычной командой `git init`.

## 3. Использовать уже установленный Postgres

**Промпт:** «Лучше используй PostgreSQL который на ПК у меня скачан, остальное как хочешь».

**Результат:** на машине оказались PostgreSQL 16 и 18. Рабочим оказался инстанс на порту **5432** (PostgreSQL 18). Создана база `testtask`.

**Что пришлось поправить:** `psql` без пароля зависал на интерактивном вводе; клиент 16-й версии ругался на служебный `\l` против сервера 18. Для метакоманд это не важно — база создалась. Пароль в Git не клали: API читает `POSTGRES_PASSWORD`.

## 4. Уточнение пароля БД

**Промпт:** пароль пользователя `postgres` (сообщён в чат, в репозиторий не записывался).

**Результат:** этого хватило, чтобы поднять схему и проверить API.

**Что пришлось поправить:** запись пароля в `dotnet user-secrets` агенту заблокировали (нельзя самостоятельно сохранять секреты). Оставили переменную окружения процесса при запуске и `.env.example` без реального пароля.

## 5. Неявный продуктовый промпт, который агент сформулировал себе сам

**Промпт:** «Сделай один API endpoint для CRM и покажи, как бы ты организовал интеграцию, без полноценной авторизации».

**Результат:** ресурс `/api/integration/leads` (`GET` + `POST`), фильтр `ApiKey` по заголовку `X-Api-Key`, общий `LeadService` с UI-контроллером `/api/leads`.

**Что доработал по ходу:** убрал шаблонный WeatherForecast, отключил редирект на HTTPS (фронт ходит на `http://localhost:5080`), фильтр в UI сделал клиентским, чтобы работали счётчики статусов. Схему БД создаёт `EnsureCreated` — для учебного мини-сервиса, не как замена миграциям.
