# TestTask — стол заявок

Небольшой внутренний сервис учёта заявок: форма, список, статусы, фильтр и сохранение в PostgreSQL. Рядом — один интеграционный endpoint, через который внешняя CRM может создать заявку и получить список.

## Как запустить

Нужны **.NET 10 SDK**, **Node.js 20+** и **локальный PostgreSQL** (на этой машине используется экземпляр на порту `5432`).

1. Создайте базу, если её ещё нет:

```sql
CREATE DATABASE testtask;
```

2. В корне репозитория задайте пароль пользователя `postgres` (он не хранится в Git):

```powershell
$env:POSTGRES_PASSWORD = "ваш_пароль"
```

3. Запустите API:

```powershell
dotnet run --project backend/src/TestTask.Api
```

API слушает `http://localhost:5080`.

4. В другом терминале поднимите UI:

```powershell
cd frontend
npm install
npm run dev
```

Откройте `http://localhost:5173`. Vite проксирует `/api` на бэкенд.

### Интеграция с CRM

Один ресурс: `/api/integration/leads`.

| Метод | Назначение |
| --- | --- |
| `GET /api/integration/leads` | Список заявок, опционально `?status=New\|InProgress\|Success\|Rejected` |
| `POST /api/integration/leads` | Создать заявку |

Ключ передаётся заголовком `X-Api-Key`. Для локального демо в `appsettings.json` стоит `local-crm-key` — это не секрет продакшена, его нужно сменить перед любой внешней сетью.

Пример:

```http
GET http://localhost:5080/api/integration/leads
X-Api-Key: local-crm-key
```

```http
POST http://localhost:5080/api/integration/leads
Content-Type: application/json
X-Api-Key: local-crm-key

{
  "name": "Клиент из CRM",
  "phone": "+7 495 000-11-22",
  "comment": "Пришло из внешней системы",
  "source": "CRM"
}
```

Готовые запросы лежат в `backend/src/TestTask.Api/TestTask.Api.http`.

## Стек

- **Backend:** ASP.NET Core 10 Web API, контроллеры, EF Core, Npgsql
- **Frontend:** React 19, TypeScript, Vite
- **БД:** PostgreSQL (уже установленный локальный инстанс, порт 5432)
- **Интеграция:** один REST-ресурс + заголовок `X-Api-Key`

## Какие решения принимал и почему

- **Один путь `/api/integration/leads`** с `GET`/`POST`, а не два разных URL: так выглядит «один endpoint» для внешней системы, при этом HTTP-методы остаются идиоматичными.
- **Общий `LeadService`** для UI и CRM: интеграция не дублирует бизнес-логику, её можно ужесточить отдельно (ключ, лимиты, аудит).
- **Пароль БД только в `POSTGRES_PASSWORD`**, в репозитории его нет. Строка подключения в `appsettings.json` без пароля.
- **`EnsureCreated` вместо миграций:** для мини-сервиса быстрее поднять схему; для долгой жизни проекта миграции надёжнее.
- **Фильтр статусов в UI на клиенте**, `?status=` на API: в интерфейсе нужны счётчики по всем статусам, CRM может забирать узкую выборку.
- **Бумажный визуальный стиль**, без UI-кита: внутренний инструмент должен читаться за несколько секунд, а не выглядеть как шаблонный дашборд.
